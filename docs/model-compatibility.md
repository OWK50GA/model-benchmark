## Gemini

Google documents image understanding and bounding boxes using `[ymin, xmin,
ymax, xmax]` normalized to 0–1000. The adapter must convert to the lab's pixel
`xyxy` convention. Structured output supports a subset of JSON Schema; do not
assume the entire internal Pydantic schema is accepted unchanged. An accepted
JSON response still needs semantic validation. No particular model availability
or current price is assumed. See [image understanding](https://ai.google.dev/gemini-api/docs/image-understanding)
and [structured outputs](https://ai.google.dev/gemini-api/docs/structured-output).

## Florence-2-large

The [Microsoft model card](https://huggingface.co/microsoft/Florence-2-large)
documents object detection, captioning, phrase grounding, and region tasks, with
`AutoProcessor`, a custom model loader using `trust_remote_code=True`, and task
post-processing. Its sample chooses float32 on CPU and float16 on CUDA. Exact
Transformers compatibility must be tested and pinned; autogenerated usage snippets
and the model's own sample may differ. Review the pinned remote code before use.

Caption text is not native structured garment attributes. Any later caption-to-
attribute conversion must be identified and evaluated as an extra pipeline step.
CPU speed and memory needs have not been measured here.

## FashionCLIP 2.0

The [author repository](https://github.com/patrickjohncyh/fashion-clip) identifies
the updated LAION-based checkpoint as FashionCLIP 2.0, while the Hub identifier
remains [patrickjohncyh/fashion-clip](https://huggingface.co/patrickjohncyh/fashion-clip).
Do not invent a separate model ID with a `2.0` suffix. The model provides visual/
textual similarity features, not native garment boxes or structured attributes.
For identity evaluation, use image embeddings and test difficult negative pairs;
semantic fashion resemblance is not proof of the same physical item.

## DINOv3

The selected [ViT-S/16 model card](https://huggingface.co/facebook/dinov3-vits16-pretrain-lvd1689m)
documents feature extraction through `AutoImageProcessor` and `AutoModel`, and
requires agreeing to the access conditions. The [official repository](https://github.com/facebookresearch/dinov3)
states that released Transformers support begins at 4.56.0. This is a minimum
documented baseline, not a tested dependency pin for this project.

The backbone exposes multiple token types; pooling and feature selection must be
fixed and recorded before similarity comparisons. Choosing a small checkpoint is
an initial integration choice, not evidence of garment identity performance.
The DINOv3 license differs from MIT; review its actual terms for the intended use.

## Questions remaining for implementation

- Which Gemini model is available to the user's account and supports the needed
  image/structured-output features?
- Which runtime versions successfully load each pinned local checkpoint on the
  target machine, and what are CPU/GPU latency and memory costs?
- What taxonomy and annotation policy will the first manually reviewed dataset use?
- Which preprocessing, crop policy, pooling method, and matching threshold perform
  well on held-out physical identities and difficult negatives?

No model-performance conclusions can be drawn until these are measured.
